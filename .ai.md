## Non-Negotiable Invariants

1. **Continuous Doc API Updates**: The [`.ai/doc-api.md`](.ai/doc-api.md) file, `api/openapi/openapi.yaml`, and the OpenAPI 3.1 endpoints (`/docs`, `/redoc`, `/api/docs`, `/openapi.json`) MUST be kept updated on **every code creation or modification**, no matter how small the change is.
2. **Secured Logging**: All logging must be structured JSON (`log/slog`). Strictly redact JWT/channel bearer tokens, webhook HMAC-SHA256 signing secrets, database/Redis credentials, and confidential notification payload texts before emission.
3. **Separation of Dispatch and Egress Delivery (ADR-001)**: The daemon strictly manages CDC event ingestion, SSE streaming, and webhook task enqueueing (`P99 <= 15ms`). Outbound HTTP POST execution, retry backoff jitter, and SSRF firewalling are strictly delegated to `rag-webhook-delivery-worker`.
4. **SSE Unification & Edge Proxy Guardrails (ADR-002)**: Serve persistent client push streams exclusively over Server-Sent Events (`text/event-stream; charset=utf-8`), setting `X-Accel-Buffering: no`, `Cache-Control: no-cache`, and immediate `http.Flusher` `: ping\n\n` frames every 15s.
5. **Targeted Node Routing Over Global Redis Fan-Out (ADR-003)**: Replace blind Redis Pub/Sub broadcast with a lightweight user/tenant node directory and targeted pod channels (`pod.{node_id}.events`) to eliminate $O(N \times M)$ message duplication.
6. **In-Memory Subscription Caching & Zero Hot-Path SQL (ADR-004)**: Store tenant routing rules and notification suppressions in pod-local read memory (`subscription_cache.go`) with asynchronous invalidation via `tenant.config.updated` ($\le 100\text{ms}$). Zero synchronous SQL reads are permitted on the hot CDC ingestion path.
7. **Bounded Ring Buffers & Slow Consumer Mitigation**: Isolate every SSE connection behind a bounded 256-event ring buffer (`ring_buffer.go`). Drop unread non-terminal progress frames when full while preserving terminal state transitions; if all 256 buffered frames are terminal and another terminal frame arrives, evict the connection immediately and rely on `Last-Event-ID` recovery to preserve the 256-event bound and non-blocking writes, and evict connections saturated for $> 5\text{ seconds}$.
8. **Staggered Draining on SIGTERM (ADR-005)**: On `SIGTERM`, mark `/ready` as `503`, stop accepting new connections, emit SSE `retry:` directives, and stagger active socket disconnections across a 30–60s randomized jitter window (`terminationGracePeriodSeconds: 75`).
9. **Memory & GC Bounds**: Configure Go 1.23+ with `GOMEMLIMIT=1800MiB` and `GOGC=80` inside `2GiB` pod memory limits (steady-state RSS $\le 1.6\text{GiB}$ across $20,000$ connections per pod).
10. **Code Cleanliness**: All Go code must pass `gofmt -s`, `go vet ./...`, `golangci-lint run`, and `go test -race ./...`.

## Git Commit Standards

- **Git Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features 
  - `fix:` for bug fixes
  - `refactor:` for code refactoring
  - `docs:` for documentation updates
  - `tests:` for tests addition and modification
  - `chore:` for maintenance tasks and environment setup

---

## Pre-Commit Verification Rules

Before committing code, submitting changes, or marking a task complete:

1. Run Go formatter and linter: `gofmt -s -w .`, `go vet ./...`, and `golangci-lint run`.
2. Run test suites with race detection: `go test -v -race ./internal/... ./test/...`.
3. Verify [`.ai/doc-api.md`](.ai/doc-api.md) and `api/openapi/openapi.yaml` are updated with all API, SSE, Protobuf, Redis, or schema modifications.
4. Verify Secured Logging rules: Ensure no raw secrets, bearer tokens, HMAC keys, or sensitive payload bodies are logged.
5. Update [`.ai/progress-tracker.md`](.ai/progress-tracker.md).
